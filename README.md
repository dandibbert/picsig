# 长截图 PicSig

iOS 长截图工具：多张截图自动拼接、录屏转长图、横竖向自定义排版、敏感信息自动打码，
以及裁剪 / 调色 / 标注 / 水印这些日常够用的编辑能力。

功能面向 Picsew 对齐，差异集中在**打码**：这里的打码不是"糊一片了事"，
而是识别 → 复核 → 遮盖 → **回读验证**的一条完整链路。

---

## 功能

### 拼接

| 模式 | 说明 |
| --- | --- |
| 自动对齐 | 按内容匹配重叠区域，自动去掉重复的状态栏 / 标签栏，接缝可手动微调 |
| 录屏转长图 | 从屏幕录制抽帧，跳过停顿帧、按内容位置排序（能处理回滚），滚动过快时报告缺口 |
| 手动排版 | 竖排 / 横排 / 网格，可调间距、外边距、对齐方式、统一格子大小、圆角与投影 |

- 竖向与横向共用一套算法：横向拼接把图片转置后跑竖向逻辑，再把几何转置回来，
  两个方向不会各自漂移（`PixelRect.transposed` / `StitchPlan.transposedPlan()`）。
- 对齐先在粗分辨率金字塔上找锚点，再在全分辨率上收敛，避免逐行暴力比对。
- 每条接缝都带置信度：低于阈值会标橙并在提示区列出，用户可以 ±4px 手动推。

### 打码（重点）

1. **识别**
   - OCR 按 2200px 高的瓦片切分后识别再合并。整张 20000px 长图直接丢给 Vision 会被降采样，
     小字（也就是电话号码所在的地方）会糊掉。
   - 规则库覆盖手机号、身份证、银行卡、邮箱、地址、姓名、车牌、快递单号、验证码、金额、
     生日、IP、网址、密钥/令牌、护照号、车架号等，附带校验：
     Luhn（银行卡）、身份证末位校验码、号段校验（手机号）、VIN 校验位。
   - 上下文加权：`收货人`、`验证码`、`余额` 这类标签会提高邻近数值的置信度；
     纯数字类别（验证码、金额）**必须**有上下文才会命中，否则误报会淹没结果。
   - 视觉类别：人脸 / 头像、二维码 / 条码由 Vision 检测，不依赖文字。
   - 同值扩散：某个值在一处被确信识别后，全图其它出现位置一并打码——
     聊天截图里手机号往往只在第一条气泡有标签。
2. **复核**
   - 结果按类别分组，逐条显示脱敏预览（`1****8`）、命中依据（"依据「收货人」判定"）与置信度。
   - 可整类开关、逐条开关，也可以直接点画布上的高亮框开关。
   - 白名单（自己公司名 / 测试号码永不打码）、黑名单（出现即打码）、自定义正则规则，
     规则编辑器带实时试跑。
3. **遮盖**
   - 五种样式：马赛克（真下采样，信息不可逆）、模糊、色块、贴纸、**脱敏替换**。
   - 脱敏替换会生成同格式、同校验位的假值，截图仍然可读——适合发给客服或写文档。
   - 字符级保留：手机号可以只留前 3 后 4，卡号只留后 4，靠字符包围盒精确切分，
     而不是整行盖掉。
   - 边距按文字高度自适应（抗锯齿的字边缘泄露得比想象中多），并对齐到像素网格，
     一页遮盖看起来是齐的而不是毛的。
   - 相邻同样式的遮盖会合并成一块，避免"一串小马赛克"。
   - UI 明确标注：模糊理论上可被还原，要彻底遮住请用马赛克或色块。
4. **验证**（其它长截图工具都没有这一步）
   - 几何检查：每条匹配应被遮住的字符区域，实际覆盖率低于 90% 会报告。
   - 回读检查：把成图重新 OCR 一遍，用比初次扫描**更低**的阈值再扫，
     如果原值还能被读出来、或遮盖区域里居然还能读出文字，就明确报告泄漏。
   - 导出前默认自动跑一次（可关）。
   - 导出默认清除 EXIF 与定位信息——像素打了码却把原始定位一起发出去等于没打。

### 编辑

裁剪、90° 旋转、镜像、亮度 / 对比度 / 饱和度 / 色温 / 锐化 / 暗角、
画笔 / 荧光笔 / 箭头 / 直线 / 矩形 / 椭圆 / 文字 / 序号标注、六种位置的水印（含平铺）。
所有操作共用一套快照式撤销栈；滑杆拖动过程只刷新预览，松手才记一步撤销。

### 导出

PNG / JPEG / HEIC，质量与缩放（原始、75%、50%、长边 4096），
超长图按"内容最安静的行"切页（附页间重叠），可同时导出 PDF，可直接存相册或走分享面板。

## 目录结构

```
PicSig.xcodeproj          Xcode 16 工程（App 目录为同步文件夹组，无需手工维护文件列表）
App/
  PicSigApp.swift          入口
  AppSettings.swift        设置持久化（UserDefaults + JSON）
  Platform/                依赖 UIKit / Vision / AVFoundation 的那一层
    GrayImageBridge.swift    CGImage/UIImage ↔ 核心类型
    TextRecognitionService   瓦片化 OCR，输出字符级包围盒
    VisualDetectionService   人脸 / 二维码检测
    StitchRenderer           按拼接方案画布渲染
    RedactionRenderer        五种遮盖样式的实际绘制
    AnnotationRenderer       标注与水印
    ImageComposer            裁剪→旋转→调色→打码→标注→水印
    VideoFrameSampler        录屏抽帧
    ImageExporter            编码、分页、PDF、相册
    RedactionCoordinator     识别→检测→规划→验证 的编排
  Features/
    Home/ Import/ Workbench/ Settings/ Shared/
  Resources/
    Localizable.xcstrings    简体中文 + English
    InfoPlist.xcstrings      权限文案
    Assets.xcassets
PicSigCore/                纯 Swift 核心包，不依赖任何 Apple 图形框架
  Sources/PicSigCore/
    Geometry/ Imaging/ Stitching/ Redaction/ Editing/ Export/
  Tests/PicSigCoreTests/
```

核心算法全部放在 `PicSigCore` 里，不 import UIKit / Vision，
因此可以在任意平台（包括 Linux CI）编译和跑测试——识别规则、校验位、拼接规划、
遮盖规划这些最容易写错也最需要回归的部分，都不需要模拟器。

## 构建与运行

需要 Xcode 16 及以上、iOS 17 及以上（用到 `@Observable` 与 SwiftUI 的新导航 API）。

```bash
open PicSig.xcodeproj      # 工程已引用本地包 PicSigCore，直接编译即可
```

命令行构建：

```bash
xcodebuild -project PicSig.xcodeproj -scheme PicSig \
           -destination 'platform=iOS Simulator,name=iPhone 16' build
```

## 测试

```bash
cd PicSigCore && swift test
```

126 个用例，覆盖重叠检测、固定区域识别、滚动 / 录屏 / 手动排版规划、
校验位、上下文判定、规则冲突、遮盖规划与合并、脱敏生成、覆盖率与回读审计、
撤销栈与分页切割。测试用的截图由 `SyntheticImage` 确定性生成，不依赖素材文件。

## 已知限制

- 录屏抽帧按固定帧率采样，极端快速的滑动仍可能留下缺口；缺口会明确报告而不是静默拼错。
- 手写规则用的是 `NSRegularExpression`，复杂的回溯正则在超长文本上会慢。
- 脱敏替换只保证格式与校验位可信，不保证与原值有任何对应关系（这正是它的目的）。
- 人脸检测用的是矩形请求（快），不做关键点对齐；侧脸小头像偶有漏检，可手动补框。
